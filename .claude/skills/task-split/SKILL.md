# task-split

Vault のルートで作業する。分解結果は**親タスク本文のチェックリスト**にする（子タスクのノートは作らない）。**ユーザーが承認・訂正するまで、ファイルを編集しない**。

## 手順
1. **対象のタスクを決める**。ユーザーが指定したものを `20_tasks/` と `00_inbox/` から探して読む。曖昧なら、候補を示して選んでもらう。
2. タスクの `project` `start` `due` `memo` と本文（タイトル＝目的、「完了条件」「経緯」）、プロジェクトノート（`10_projects/<名前>/<名前>.md` の目的）を読み、**分解案を推論で作る**。
   - 項目は、完了を判定できる粒度にする（目安は3〜8個。細かすぎる作業は束ねる）。
   - 根拠のない項目や期限は作らない。期限は、タスクの `start` / `due` などから妥当と言える場合に限り、案として付ける。
3. 次の書式で**案を提示**し、承認・訂正を求める。
   ```
   - [ ] 項目名 期限:YYYY-MM-DD
   ```
   期限は任意（無ければ `期限:` ごと省く）。
4. 承認後、タスク本文の `## チェックリスト` の見出しの下（次の `## ` の前）に書き込む。見出しがなければ、`## 経緯` の前（それもなければ本文の末尾）に `## チェックリスト` を作って書く。既存の項目は置き換えず、重複を除いて追記する。frontmatter は変更しない。
5. 結果を「書き込んだ項目・次にやること」で簡潔に報告する。ガントには、タスクの編集後のフックで自動で反映される（Obsidian で編集したときは `gantt-update`）。

## 注意
- マイルストーンは、ガントではタスクの開始日の位置に表示される。期限は名前の後ろに付くだけで、位置は変わらない。期限が基準日を過ぎた未完了項目は赤、完了項目（`- [x]`）はグレーになる。
- 項目は完了したら `- [x]` にする（ユーザーが行う。タスク自体の `status: done` / `completed` とは別）。
- 外部サービスへ情報を送らない。
