# knowledge-harvest

Vault のルートで作業する。**ユーザーが承認するまで、ノートを作らず、印も付けない**（`daily-end` から呼ばれたときは、`daily-end` の1回の承認に含めて確認する）。

## 手順
1. 対象を集める。次のコマンドを**そのまま**実行する。
   ```
   python "${CLAUDE_SKILL_DIR}/harvest.py" targets
   ```
   出力（JSON）:
   - `memo`: 今日のデイリーの「今日のメモ」の、印のない項目
   - `tasks`: 前回の棚卸し（`since`）以降に更新したタスク。`progress` は「経緯」の、印のない行
   必要なら、タスクのノート本体（完了条件・成果）と、`80_context/_index.md` も読む（既存の記録と重複させないため）。
2. 各項目・各行から、**残す価値のあるもの**を選び、行き先を決める（残す価値がなければ「残さない」。経緯の行は消さない）。
   | 行き先 | 置き場所とテンプレート | 何を入れるか |
   |---|---|---|
   | 技術知見 | `80_context/knowledge/<名前>.md`（`context-knowledge.md`） | Claude の作業に効く、短く指示的な知見（手順のコツ、ツールの癖、環境の事実） |
   | 判断記録 | `80_context/decisions/<名前>.md`（`decision.md`） | 選択肢から何かを選んだこと。背景・選択肢・決定・理由・影響・見直す条件 |
   | 失敗記録 | `80_context/mistakes/<名前>.md`（`mistake.md`） | うまくいかなかったこと。何が起きたか・原因・対策・再発防止のルール（Claude が守る1〜2行の指示） |
   | knowledge | `30_knowledge/<名前>.md`（`knowledge.md`） | 人が読み返す解説・手順・ノウハウ |
   | research | `40_research/<今日 YYYY-MM-DD>_<名前>.md`（`research.md`） | 外部の出典に基づく調べもの（URL だけのメモも含む）。主な URL を `source` に入れる |
   | doc | プロジェクトに属せば `10_projects/<名前>/`、属さなければ `50_documents/`（`document.md`） | まとまった資料 |
   | タスク | `00_inbox/<タスク名>.md`（`task.md`、`status: idea`） | 今日のメモのうち、やること（電話の依頼など）。本文の「経緯」に `### YYYY-MM-DD` を付けてメモの内容を書く |
   - 同じ話題の既存のノートがあれば、新しく作らずに**追記**する（本文の末尾、または該当の節に `### 追記 YYYY-MM-DD` を付けて足す）。研究は日付違いの同名も既存とみなす。
   - 名前は日本語で簡潔に。Windows で使えない文字 `\ / : * ? " < > |` は除く。
   - `project` は、タスクの `project` か、内容から明らかなプロジェクト（`10_projects/` の直下のフォルダ名）を `"[[プロジェクト名]]"` で入れる。なければ空。
   - タグは CLAUDE.md のタグの規約に従う（既存のタグを `^tags:` の Grep で集め、分野のタグを1〜3個。確認は不要。新規のタグは報告で知らせる）。
   - 本文は、メモと経緯に書かれた内容だけで書き、足さない。確かめていないことは「未確認」と書く。
3. **進捗ログの更新案**も作る。更新したタスクがあるプロジェクトごとに、`80_context/projects/<プロジェクト名> 進捗ログ.md`（なければ `progress.md` から作る。`project` を入れる）について:
   - 「現在の要約」（いまの状況・次の一手・課題・リスク・最終更新）を書き換える。
   - 「ログ」の先頭（新しい日付が上）に `### YYYY-MM-DD` を足し、進んだこと・次の一手・課題を書く（同じ日付があれば追記）。
4. **案を表で示す**: 元（メモの抜粋かタスク名と行）・行き先・ノート名（新規か追記か）・`project`・タグ（新規は明記）・理由。進捗ログの更新案も示す。承認・訂正を1回で受ける。
5. 承認されたら書く。
   - ノートを作る・追記する（frontmatter はテンプレートのとおり。`created` と `date` は今日）。
   - 元の行に印を付ける: 取り出した**今日のメモの項目**と**経緯の行**の行末に ` → [[ノート名]]`（複数なら ` → [[A]] [[B]]`）を足す。ほかの文言は変えない。
   - 取り出したタスクの「成果」の節に `- [[ノート名]]` を足す（重複は足さない）。
   - 進捗ログを更新する。
6. 次のコマンドを**そのまま**順に実行する（索引と再発防止のルールの再生成、棚卸しの日時の記録）。棚卸しで何も残さなかった場合も実行する。
   ```
   python "${CLAUDE_SKILL_DIR}/harvest.py" index
   python "${CLAUDE_SKILL_DIR}/harvest.py" mark
   ```
7. 報告: 作ったノート・追記したノート（付けたタグ。新規のタグは明記）・更新した進捗ログ・次にやること。

## 注意
- 印（` → [[`）のある行は取り出し済み。二重に取り出さない。過去のデイリーのメモは対象にしない。
- `80_context/_index.md` と `_rules.md` は自動生成なので、手で編集しない。
- このスキルの中では調べもの（Web 検索など）をしない。外部サービスへ情報を送らない。秘密情報（トークン、キー）をノートに書かない。
- 会話の途中で判断や失敗が起きたときは、締めを待たずに、このスキルの手順2〜6で1件だけ記録してよい（ユーザーの承認を得てから）。
- テスト: `python -m unittest discover -s .claude/skills/knowledge-harvest/tests`
