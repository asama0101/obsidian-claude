# knowledge-harvest

Vault のルートで作業する。**ユーザーが承認するまで、ノートを作らず、印も付けない**（`daily-end` から呼ばれたときは、`daily-end` の1回の承認に含めて確認する）。

## 手順
1. 対象を集める。次のコマンドを**そのまま**実行する。
   ```
   python "${CLAUDE_SKILL_DIR}/harvest.py" targets
   ```
   出力（JSON）:
   - `memo`: 今日のデイリーの「今日のメモ」の、印のない項目
   - `tasks`: 前回の棚卸し（`since`）以降に更新したタスク。`progress` は「経緯」の、印のない行
   必要なら、タスクのノート本体（完了条件・成果）と、`80_context/_index.md`（必要なら4つのファイル本体）も読む（既存の記録と重複させないため）。
2. 各項目・各行から、**残す価値のあるもの**を選び、行き先を決める（残す価値がなければ「残さない」。経緯の行は消さない）。
   | 行き先 | 置き場所とテンプレート | 何を入れるか |
   |---|---|---|
   | 技術知見 | `80_context/技術知見.md` の1件（下の「80_context の書式」） | Claude の作業に効く、短く指示的な知見（手順のコツ、ツールの癖、環境の事実） |
   | 判断記録 | `80_context/判断記録.md` の1件（同上） | 選択肢から何かを選んだこと |
   | 失敗記録 | `80_context/失敗記録.md` の1件（同上） | うまくいかなかったこと |
   | knowledge | `30_knowledge/<名前>.md`（`knowledge.md`） | 人が読み返す解説・手順・ノウハウ、外部の出典に基づく調べもの（URL だけのメモも含む）。出典があれば主な URL を `source` に入れる |
   | doc | プロジェクトに属せば `10_projects/<名前>/`、属さなければ `50_documents/`（`document.md`） | まとまった資料 |
   | タスク | `00_inbox/<タスク名>.md`（`task.md`、`status: idea`） | 今日のメモのうち、やること（電話の依頼など）。本文の「経緯」に `### YYYY-MM-DD` を付けてメモの内容を書く |
   - 同じ話題の既存のノート（80_context では既存の件）があれば、新しく作らずに**追記**する（ノートは本文の末尾か該当の節に `### 追記 YYYY-MM-DD` を付けて足す。80_context の件は書式のとおり）。
   - 名前（80_context では件のタイトル）は日本語で簡潔に。Windows で使えない文字 `\ / : * ? " < > |` と `#` `[` `]` `^` は除く。
   - `project` は、タスクの `project` か、内容から明らかなプロジェクト（`10_projects/` の直下のフォルダ名）を `"[[プロジェクト名]]"` で入れる。なければ空。80_context の件では「プロジェクト」の項目に `[[プロジェクト名]]` で書く（なければ項目ごと省く）。
   - 本文は、メモと経緯に書かれた内容だけで書き、足さない。確かめていないことは「未確認」と書く。
3. **進捗ログの更新案**も作る。更新したタスクがあるプロジェクトごとに、`80_context/進捗ログ.md` の `## プロジェクト名` の節（なければ足す）について:
   - 「### 現在の要約」（いまの状況・次の一手・課題・リスク・最終更新）を書き換える。
   - 「### ログ」の先頭（新しい日付が上）に `#### YYYY-MM-DD` を足し、進んだこと・次の一手・課題を書く（同じ日付があれば追記）。
4. **案を表で示す**: 元（メモの抜粋かタスク名と行）・行き先・ノート名（新規か追記か。80_context は `ファイル#タイトル`）・`project`・理由。進捗ログの更新案も示す。承認・訂正を1回で受ける。
5. 承認されたら書く。
   - ノートを作る・追記する（frontmatter はテンプレートのとおり。`created` は今日）。80_context の件は、下の書式のとおりに書く。
   - 元の行に印を付ける: 取り出した**今日のメモの項目**と**経緯の行**の行末に ` → [[ノート名]]`（80_context は ` → [[判断記録#タイトル]]`。複数なら ` → [[A]] [[B]]`）を足す。ほかの文言は変えない。
   - 取り出したタスクの「成果」の節に `- [[ノート名]]` を足す（80_context は `- [[判断記録#タイトル]]`。重複は足さない）。
   - 進捗ログを更新する。
6. 次のコマンドを**そのまま**順に実行する（索引と再発防止のルールの再生成、棚卸しの日時の記録）。棚卸しで何も残さなかった場合も実行する。
   ```
   python "${CLAUDE_SKILL_DIR}/harvest.py" index
   python "${CLAUDE_SKILL_DIR}/harvest.py" mark
   ```
7. 報告: 作ったノート・追記したノート・更新した進捗ログ・次にやること。

## 80_context の書式
Claude のインプットは、種類ごとに1ファイル（`80_context/技術知見.md`・`判断記録.md`・`失敗記録.md`・`進捗ログ.md`）。テンプレートはなく、この節が書式の正本。`harvest.py index` がこの書式を解析して索引とルールを作るので、崩さない。
- プロパティ（frontmatter）は付けない。ファイルがなければ、1行目に `# 技術知見` などの見出し、空行、`%% 書式は knowledge-harvest の SKILL.md。1件は「## タイトル」、新しい件を先頭に %%`（進捗ログは `%% 書式は knowledge-harvest の SKILL.md。プロジェクトごとに「## プロジェクト名」 %%`）を置いて作る。
- 1件は `## タイトル`。タイトルはファイルの中で一意にする（同じ話題は追記する）。新しい件は、冒頭のコメントの直後（最初の `## ` の前）に足す。
- 項目は `- 項目名: 内容` を、下の順で書く。内容が長いときは、その下に字下げした箇条書きで続ける（`- 選択肢:` の下に `  - A 案` など）。「プロジェクト」は任意、ほかは書けるものを書く。
- 追記は、その件の末尾に `- 追記 YYYY-MM-DD: 内容` を足す（決定や再発防止のルールが変わったときは、その項目も書き換える）。
- 日付は判断・失敗・知見の日（`YYYY-MM-DD`）。

| ファイル | 項目（この順） | 索引に出る項目 |
|---|---|---|
| 技術知見 | 日付 / プロジェクト / 要約（Claude が作業で使う形で、短く指示的に1〜3行） / 内容 / 出典 | 要約 |
| 判断記録 | 日付 / プロジェクト / 背景 / 選択肢 / 決定 / 理由 / 影響 / 見直す条件 | 決定 |
| 失敗記録 | 日付 / プロジェクト / 何が起きたか / 原因 / 対策 / 再発防止のルール（Claude が守る1〜2行の指示。複数なら字下げした箇条書きで1行1つ。`_rules.md` に集められる） | 何が起きたか |

例（判断記録）:
```markdown
## 通知の頻度を応答ごとにする
- 日付: 2026-10-04
- プロジェクト: [[Vaultの改善]]
- 背景: …
- 選択肢:
  - 応答ごと
  - 作業の区切りごと
- 決定: 応答ごとにする
- 理由: …
- 影響: …
- 見直す条件: …
```

進捗ログ（プロジェクトの節は名前の順。索引には「現在の要約」の先頭4行が出る）:
```markdown
## Vaultの改善
### 現在の要約
- いまの状況: …
- 次の一手: …
- 課題・リスク: …
- 最終更新: YYYY-MM-DD

### ログ
#### YYYY-MM-DD
- 進んだこと: …
- 次の一手: …
- 課題: …
```

## 注意
- 印（` → [[`）のある行は取り出し済み。二重に取り出さない。過去のデイリーのメモは対象にしない。
- `80_context/_index.md` と `_rules.md` は自動生成なので、手で編集しない。
- このスキルの中では調べもの（Web 検索など）をしない。外部サービスへ情報を送らない。秘密情報（トークン、キー）をノートに書かない。
- 会話の途中で判断や失敗が起きたときは、締めを待たずに、このスキルの手順2〜6で1件だけ記録してよい（ユーザーの承認を得てから）。
- テスト: `python -m unittest discover -s .claude/skills/knowledge-harvest/tests`
