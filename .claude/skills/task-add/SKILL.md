# task-add

Vault のルートで作業する。思いつきをすぐタスクにする入口。ノートは `90_system/templates/task.md` に従い、`00_inbox/<タスク名>.md` に作る。確認は取らずに作る。

## 手順
1. **タスク名を決める**。タスク名は目的を表す（日本語・簡潔。Windows で使えない文字 `\ / : * ? " < > |` は除く）。
   - 名前から目的が読み取れない（「資料」「確認」だけ、何をどうするかが分からない）ときは、作る前に、目的が分かる名前の案を1つ示して一言だけ確かめる。
   - `00_inbox/` と `20_tasks/` に同名のノートがあれば、上書きせず、別名を提案する。
2. テンプレートのとおりに作る。`status: idea`、`start` / `due` / `completed` / `project` は空、`created` は今日。本文はテンプレートの見出し（完了条件 / チェックリスト / 経緯 / 成果）のまま。
   - ユーザーの発言に、すでに決まっていること（やると決めている・期限・プロジェクト・背景）があれば、それだけを反映する。やると決めていて日付があれば `status: todo` と `start` / `due`（片方だけなら、もう片方は当日）。背景は「経緯」に `### YYYY-MM-DD` の見出しを付けて書く。書かれていないことは足さない。
3. 結果を「作ったタスク（場所と状態）・反映した値・次にやること」で簡潔に報告する。次にやることの例: 振り分けは `daily-end`、分解は `task-split`、任せるなら `task-run`。

## 注意
- 振り分け（`project` を決めて `20_tasks/` へ移す、状態と日付を決める）は `daily-end` が行う。このスキルでは移動しない。
- 既存のタスクは変更しない。
- 完了済みとして作る場合は `status: done` と `completed` の両方を入れる。
