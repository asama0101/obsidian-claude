# project-add

Vault のルートで作業する。ノートは `90_system/templates/project.md` に従う。

## 手順
1. **プロジェクト名を決める**（ユーザーが指定。ファイル名・フォルダ名に使うため、Windows で使えない文字 `\ / : * ? " < > |` は除く）。`10_projects/<名前>/` が既にあれば、上書きせずに伝えて終了する。
2. 目的・開始日（`start`）・期限（`due`）が分かれば聞き取る（無ければ空のまま。聞き返しすぎない）。
3. **プロセスのフォルダ案を提示する**。次の初期セットを示し、不要なものの削除・追加をユーザーが指示して確定する（承認を得てから作る）。
   - 横断: `00_管理` / `01_課題・リスク管理` / `02_現行情報` / `03_参考資料・外部情報` / `04_マニュアル` / `05_イベント`
   - 工程（5 刻み。あとから間に差し込める）: `10_見積・稟議` / `15_契約・発注` / `20_要件定義` / `25_設備設計` / `30_工事設計` / `35_構築` / `40_組込作業` / `45_設備検証` / `50_検収・完了報告` / `55_運用引継` / `60_保守・問い合わせ`
   - プロジェクトの内容から、推奨する構成（例: 設備工事を伴わない場合に外すもの）を一言添える。
4. 承認後に作成する。
   - `10_projects/<名前>/<名前>.md`: テンプレートのとおり。`status: active`、`start`・`due`（あれば）、`created`（今日）。`## 目的` に聞き取った内容を書く。
   - 承認されたプロセスのサブフォルダ。空のフォルダは OneDrive の同期や Obsidian の一覧で見落としやすいため、各フォルダに空の `.gitkeep` を置く。
5. 結果を「作ったノートとフォルダ・次にやること（タスク追加は `task-add`）」で簡潔に報告する。

## 注意
- タスクは `20_tasks/` に置く（プロセスのフォルダには入れず、`project` プロパティで紐づける）。
- 既存のファイル・フォルダは変更しない。
