# knowledge-add

Vault のルートで作業する。ノートは `90_system/templates/knowledge.md` か `90_system/templates/research.md` に従う。**ユーザーが確認するまで、ファイルを作らない**（daily-end から使うときは、daily-end の承認で確認済みとする）。

## 手順
1. **ブランチを確かめる。** `git branch --show-current` が `main` なら、書かずに「`daily-start` で当日のブランチを作ってから保存する」と伝えて終了する。
2. **残す内容を決める。** ユーザーの指定（直前の調べもの、会話のある部分、貼られた文章など）を使う。範囲が曖昧なら、候補を示して聞く。
3. **種類を決める。** 迷うときは推奨と理由を示す。
   - research: 外部の出典（Web ページ・文書・仕様書など）に基づく調べもの。
   - knowledge: 自分の理解・手順・ノウハウ・決めごと（出典があってもよい）。
4. **名前を決める。** 日本語で簡潔に。Windows で使えない文字 `\ / : * ? " < > |` は除く。
   - knowledge: `30_knowledge/<名前>.md`
   - research: `40_research/<今日 YYYY-MM-DD>_<名前>.md`
   - 同じ名前のノート（research は日付違いも含む）があれば、上書きしない。既存の中身を読み、「既存に追記する」か「別名で作る」かを聞く。
5. **project を決める。** `10_projects/` の直下のフォルダ名がプロジェクト名。関係が明らかなものがあれば `"[[プロジェクト名]]"` を推奨し、無ければ空。
6. **タグを決める**（CLAUDE.md のタグの規約に従う。ユーザーへの確認は不要）。
   - 既存のタグを、`30_knowledge/`・`40_research/`・`50_documents/`・`10_projects/` の frontmatter の `tags` から集める（Grep で `^tags:` を探す）。
   - 分野のタグを1〜3個。既存のタグに当てはまるものがあればそれを使い、同じ分野に別名のタグを作らない。
7. **本文を作る。** 会話にある内容だけで書き、書かれていないことを足さない。確かめていないことは「未確認」と書く。
   - knowledge: `## 要約`（2〜3行）・`## 内容`・`## 注意点`・`## 出典`（無ければ「なし」）。
   - research: `## 結論`・`## 詳細`。主な出典の URL を `source` に入れ、ほかの出典は `## 詳細` の末尾に箇条書きにする。
8. **案を示して確認する。** 種類・保存先のパス・`project`・`tags`（新しく作るタグは「新規」と添える）・本文の全文を示し、1回で確認する。訂正があれば反映する。
9. **作る。** frontmatter はテンプレートのとおり（`created` は今日）。既存に追記する場合は、本文の末尾に `## 追記 YYYY-MM-DD` の節を足し、ほかの部分は変えない。
10. **報告する。** 作ったノートのパス、付けたタグ（新規のタグがあれば明記）、`project` を付けた場合はプロジェクトノートの「知識・資料」に出ることを、簡潔に伝える。

## 注意
- このスキルの中では調べもの（Web 検索など）をしない。保存するのは、会話ですでに得た内容だけ。
- 外部サービスへ情報を送らない。秘密情報（トークン、キー）をノートに書かない。
- 既存のノートは、承認された追記のほかは変更しない。
