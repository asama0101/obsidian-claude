# meeting-import

Vault のルートで作業する。議事録の書式は `90_system/templates/meeting.md`、タスクの書式は `90_system/templates/task.md`。**議事録の内容の書き込み・タスクの作成・印付けは、案を示してユーザーが承認したものだけ**行う。

- アクションアイテムの書式: `- [ ] 内容 期限:YYYY-MM-DD`（期限は省略可）。担当は書かない（他の人に頼んだものは、タスクの状態 `requested` で表す）。
- 処理済みの印: 行末の ` → [[タスク名]]`（スクリプトが付ける）。印のある行、完了（`- [x]`）の行は対象外。

## 会議の情報の取り込み元
1. **Microsoft 365 コネクタ**（Anthropic 公式。使えるのはテナントの管理者が同意した後）: このセッションで Outlook の予定表・Teams の会議の文字起こしなどを読むツールが使えるときだけ使う。読み取りだけを行い、メールの送信や予定の変更はしない。使えなければ、2・3 で作る。
2. **00_inbox のファイル**: Teams の「要約」からダウンロードした文字起こし（`.vtt` / `.docx`）や会議のメモ（`.txt` / `.md`）。読むときは次のコマンドを使う（ファイルのパスはシングルクォートで囲む）。
   ```
   python "${CLAUDE_SKILL_DIR}/transcript.py" '<ファイルのパス>'
   ```
3. **貼り付け**: 議事録ノートや会話に貼り付けた、Teams の要約・ファシリテーターのメモ・手書きのメモ。

## 手順A: 議事録を作る・仕上げる
1. **会議を決める。** ユーザーの指定（会議名・日付・ファイル）から決める。指定がなければ、`70_meetings/` で今日の日付から始まる議事録と、`00_inbox/` の文字起こしを候補として示す。
2. **議事録ノートを用意する。** 既にあればそれを使う。無ければ `70_meetings/<開催日 YYYY-MM-DD>_<会議名>.md` をテンプレートから作る案にする（`date` は開催日、`created` は今日、`project` は会議名・参加者・内容から明らかなときだけ推奨し、なければ空）。
3. **中身を整える案を作る。** 取り込み元の内容だけを使い、書かれていないことを足さない。確かめていないことは「未確認」と書く。
   - `location`: 開催場所（予定の場所。会議室名・Teams など。分からなければ空）
   - `## 参加者`: 1人1行で `- 名前（所属・役割は任意）`（予定の出席者か、文字起こしの話者）
   - `source`: 取り込み元（コネクタなら会議の URL・ID、ファイルなら元のファイル名）
   - `## 目的・議題`・`## 議事・決定事項`: 要点を箇条書きで。決定事項は「決定:」で始める
   - `## アクションアイテム`: やることを書式どおりに抜き出す（期限が言及されていれば `期限:` を付ける）。誰が担当かは書かない
   - `## 参照ドキュメント`: 言及された資料
   - 要約・文字起こしの全文を残したいときは、`## 記録` の節を末尾に足して転記する（長い文字起こしは、元のファイルを添付として残し、要約だけにしてもよい。どちらにするかは案で聞く）
4. **案を示し、承認を1回得る。** 承認されたら議事録を書く（既存の議事録は、ユーザーの書いた文言を消さず、足りない節に足す）。00_inbox の元のファイルは、承認を得て `90_system/attachments/` に移し、議事録の `## 参照ドキュメント` から `[[ファイル名]]` でリンクする。
5. 続けて手順Bでタスクにする（ユーザーが不要と言えば省く）。

## 手順B: アクションアイテムをタスクにする
コマンドは、下に書いた形のまま実行する（改変したり、自己流のコマンドを足したりしない）。議事録名・タスク名・項目の文言などの値は、シングルクォートで囲んで渡す（ダブルクォートの中では `$` やバッククォートが展開され、値が黙って変わるため）。値の中の `'` は `'\''` と書く。

1. **項目を取得する。** `python "${CLAUDE_SKILL_DIR}/meeting_actions.py" list --meeting '<議事録名>'` を実行する。
   - `not_found` なら、議事録名を確認し直す。`invalid` なら、`problems` を伝えて終える。
   - `items` が空なら、その旨を伝えて終える。
   - 結果の `project` が議事録のプロジェクト（無ければ空）、`date` が開催日。各項目は `text`（本文そのもの。手順4で使う）・`content`（内容）・`due`（期限）。
2. **案を一覧で示し、まとめて1回だけ確認する。** 各項目について、タスクにするか、タスク名、状態、`start`、`due`、`project` の案を表にする。
   - タスク名: `content` を、目的が分かる日本語に簡潔に整える。Windows で使えない文字 `\ / : * ? " < > |` は除く。`20_tasks/` と `00_inbox/` に同名があれば、別名を提案する。
   - 状態: `todo`（自分でやる）か `requested`（他の人に頼んで待つ）。会議の内容から推奨し、ユーザーが1件ずつ選ぶ。
   - `start`: 既定は今日。`due`: 項目の `due`。無ければ今日（推測で別の日にしない。表で「既定」と分かるようにする）。
   - `project`: 既定は議事録の `project`。
   - 案を確定させず、ユーザーが確認・訂正した値だけを使う。タスクにしない項目は、そのまま残す。
3. **タスクを作る。** 承認された項目ごとに、`90_system/templates/task.md` に従って `20_tasks/<タスク名>.md` を作る（会議で決まったものは振り分け済みとみなし、インボックスを通さない）。
   - `status`（`todo` か `requested`）、`project: "[[プロジェクト名]]"`（無ければ空）、`start`・`due`、`completed` は空、`created` は今日、`tags: []`。`requested` のときは `memo` に依頼の相手と内容が分かれば書く。
   - `project` の次の行に `meeting: "[[<議事録名>]]"` を足す（このスキルで作るタスクだけが持つプロパティ）。
   - 本文はテンプレートの見出しのまま、`## 経緯` に `### <今日>` と `- 議事録 [[<議事録名>]] のアクションアイテム「<content>」から作成。` を書く。
   - 既存のノートは上書きしない。
4. **議事録に印を付ける。** 作ったタスクごとに、`python "${CLAUDE_SKILL_DIR}/meeting_actions.py" link --meeting '<議事録名>' --text '<手順1の text>' --task '<タスク名>'` を実行する。
   - `text` は手順1の結果をそのまま使う（行番号でなく文言で指定する）。
   - 結果が `linked` 以外のときは、タスクを作り直さない。手順1の `list` をもう一度実行して、議事録の現在の文言を確かめる（確認のあいだに Obsidian で書き換えられた可能性がある）。作成済みのタスク名と現在の文言をユーザーに示し、確認を取ってから、現在の文言で `link` だけをやり直す。
5. **報告する。** 作った議事録、作ったタスクの一覧（名前・状態・プロジェクト・開始日〜期限）、タスクにしないで残した項目を伝える。ガントは、タスクの作成後のフックで自動で更新される。

## 手順C: 朝の枠作り（daily-start から）
Microsoft 365 コネクタが使えるときだけ行う。使えなければ何もしない（「コネクタが使えないため、議事録の枠は作っていない」と1行伝える）。
1. 今日の予定（Teams 会議を含む）を読み取りだけで取得する。
2. 予定ごとに、`70_meetings/<今日>_<会議名>.md` が無ければ、テンプレートから枠を作る（`date`・`location`・`source`、予定の出席者を `## 参加者` に、予定の説明欄にある議題を `## 目的・議題` に入れる）。既にあれば触らない。枠は確認なしで作ってよい（中身は予定の情報だけのため）。
3. 作った枠の一覧を伝える。

## 注意
- `## 議事・決定事項` などからは、承認なしにタスクを作らない。
- 議事録の frontmatter や、ほかの行は、承認された書き込みのほかは書き換えない（印を付けるのはスクリプトだけ）。
- 外部サービスへ情報を送らない（コネクタは読み取りだけ）。
