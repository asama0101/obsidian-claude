# タスクとインボックス

## タスクのプロパティ
- `status`・`project`・`start`・`due`・`completed`・`memo`（自由記入。保留や依頼の理由など）。
- `idea` のときは `start` / `due` を空にする。`todo` 以降にするときに日付を入れる（指定がなければ当日。当日開始の `todo` はすぐ「遅れ」に出るが、気づけるようにする意図どおり）。
- 完了したら `status: done` と `completed` を必ず入れる（デイリーのダッシュボードが `completed` を見る）。
- 中止・不要になったタスクは削除せず `cancelled` にする。
- `meeting: "[[議事録名]]"` は、`meeting-import` が議事録から作ったタスクだけが持つ。

## タスクの本文
- 目的はタイトル（ファイル名）で示す。タイトルから目的が読み取れないときは、名前の変更を提案する。
- 見出しはテンプレート `90_system/templates/task.md` の順:
  - `## 完了条件`: 任意。`task-run` の grilling で埋まる。
  - `## チェックリスト`: `- [ ] 項目 期限:YYYY-MM-DD`（期限は任意）。ガントに出す項目は `<!-- gantt:start -->` 〜 `<!-- gantt:end -->` の間に書く。マーカーは消さない。
  - `## 経緯`: `### YYYY-MM-DD` の見出しで日ごとに追記する。
  - `## 成果`: 成果物と、棚卸しで作ったノートへのリンク。
- 行末の ` → [[ノート名]]` は棚卸しで取り出し済みの印。消したり書き換えたりしない。

## インボックスと振り分け
- 新しいタスクは `00_inbox/` に `idea` で作る。会議で決まったタスクだけは、`meeting-import` が `20_tasks/` に直接作る。
- フォルダは「振り分け済みか」、`status` は「やると決めたか」を表す。別々に扱う。
- 振り分けは `daily-end` が案を出し、承認後に移す。タスクは `20_tasks/` へ、セッションと資料はプロジェクトに属せば `10_projects/<名前>/`、属さなければ `50_documents/` へ。文字起こしは `meeting-import` で議事録にする。迷うものは聞く。
- grilling-html のセッションのフォルダ名は `<日時>_grilling_<テーマ>/`。
